1The model

Setting up the penetration process as a sum of i.i.d. increments.

We have n systems and m attackers. The way I modelled it is this: every attacker goes through the n systems one after the other, and at step i (system i) it gets a score Xi. The steps are independent and identically distributed, and different attackers are independent of each other. So each attacker produces one trajectory

S0 = 0,   Sk = X1 + … + Xk   (k = 1, …, n)

and the m attackers give m independent sample trajectories of the same process. In practice n is the "length" of each trajectory and m is how many trajectories we have to estimate distributions, which is why the choice of m matters (more on this in section 5).

The two score models

Bernoulli

Xi ∈ {0, 1}, P(Xi = 1) = p.

1 means the attacker got into system i, 0 means it didn't. Then Sn is the number of systems penetrated (so Sn ~ Bin(n, p)) and Sn/n is the fraction of systems penetrated.

μ = E[X] = p,   σ² = Var(X) = p(1 − p).

In the Python tables I used p = 0.3 (σ² = 0.21). In the simulator p can be changed.

Rademacher

Xi ∈ {−1, +1}, each with probability 1/2.

+1 means the attacker gains ground on system i, −1 means the defence pushes it back. It's the symmetric, zero-mean case: attacker and defender are perfectly balanced, and Sk is a simple symmetric random walk.

μ = 0,   σ² = 1.

Here Sn = 2·Bin(n, 1/2) − n, so it only takes values with the same parity as n.

What theory says about the three quantities

Using only linearity of the mean and independence (variances add up), for i.i.d. increments with mean μ and variance σ²:

QuantityMeanVarianceBernoulli (p)RademacherAs n → ∞
Snnμnσ²mean np, var np(1−p)mean 0, var nspreads out, variance grows like n
Sn/nμσ²/nmean p, var p(1−p)/nmean 0, var 1/nvariance → 0, concentrates at μ (LLN)
Sn/√nμ√nσ²mean p√n → ∞, var p(1−p)mean 0, var 1variance stays fixed; for μ = 0 the shape → N(0, σ²) (CLT)

So the three normalizations are dividing by n0, n1 and n1/2. Dividing by n is "too much" (everything collapses to a point), not dividing is "too little" (everything blows up), and √n is exactly the scale at which the random fluctuations stay of order one. The rest of the homework is basically checking this with simulations.

For the Bernoulli model Sn/√n does not converge to anything because its mean p√n goes to infinity. The CLT still holds, but for the centred version (Sn − np)/√(np(1−p)). This is one of the reasons the Rademacher model is introduced: with zero mean and unit variance, Sn/√n is already the standardized sum.

What I see in the trajectories. With the Bernoulli model the paths of Sk all go up along the line pk and slowly spread apart. The paths of Sk/k jump around a lot at the beginning (after one system the average is either 0 or 1) and then get squeezed toward p, inside a band that shrinks like 1/√k. The paths of Sk/√k keep the same width all the time, but in the Bernoulli case they drift upwards like p√k. With the Rademacher model the Sk paths wander up and down around 0 without any trend, and the band ±2√k grows like a parabola lying on its side. The Sk/√k paths stay inside roughly ±2 forever, without settling down: each single path keeps moving, it's only the distribution across attackers that stabilizes.

3Variance under the three normalizations

How the spread of each quantity changes as n grows.

For this part I ran the simulation for n = 10, 100, 1,000, 10,000 and 100,000 with m = 10,000 attackers for each n (Python, p = 0.3 for Bernoulli). For the big values of n simulating every single step would be 10⁹ random numbers, so for the table I used the fact that the sum of the increments has exactly the binomial distribution (Bin(n, p) for Bernoulli, 2·Bin(n, 1/2) − n for Rademacher). I checked on n = 1,000 that the step-by-step simulation and this shortcut give the same distribution (two-sample KS test p-values 1.00 and 0.99).

Var(Sn)Var(Sn/n)Var(Sn/√n)dots = simulation, dashed = theory

On a log-log plot the three variances are straight lines with slopes +1, −1 and 0, exactly as predicted by nσ², σ²/n and σ². The simulated values are always within a few percent of the theory (for example for Rademacher, Var(Sn/√n) was 1.009, 0.977, 1.023, 1.013 and 1.003). The small differences are just Monte Carlo error: with m = 10,000 the sample variance itself has a relative error of about √(2/m) ≈ 1.4%.

The means behave as expected too: for Bernoulli the mean of Sn/√n went 0.95, 3.0, 9.5, 30, 94.9 (= 0.3·√n), so even though its variance is stable the distribution keeps moving to the right. For Rademacher all three means stay at 0.

4Law of Large Numbers: Sn/n → μ

Convergence in probability of the average score.

The weak LLN says that for every ε > 0

P( |Sn/n − μ| > ε ) → 0   as n → ∞.

The quickest proof is Chebyshev's inequality with the variance from section 1: P(|Sn/n − μ| ≥ ε) ≤ σ²/(nε²). Since our increments are bounded, there is also the (much stronger) Hoeffding bound P(|Sn/n − μ| ≥ ε) ≤ 2·exp(−2nε²/(b − a)²), with b − a = 1 for Bernoulli and 2 for Rademacher. To "see" convergence in probability I estimated the left side as the fraction of the m attackers whose average is more than ε away from μ, for many values of n.

Comments.

  • The probability goes to 0 in every case, and for large n it goes to 0 fast: with Bernoulli and ε = 0.05 it was 0.24 at n = 100, 0.0006 at n = 1,000 and 0 out of 10,000 at n = 10,000. The Hoeffding bound shows why: the decay is exponential in n, not just like 1/n.
  • Chebyshev is always respected but it is very loose (it is a bound that works for any distribution with that variance, so it can't be tight for ours). For large n it overestimates by many orders of magnitude.
  • The smaller ε is, the larger n has to be. Roughly, the deviation of Sn/n is of size σ/√n, so we need n ≫ σ²/ε². For Rademacher with ε = 0.01 that is n ≫ 10,000, and in fact at n = 10,000 still 31% of the attackers were outside the band. This is the link between the LLN and the CLT: the LLN says the error goes to 0, the CLT says how fast (like 1/√n).
  • For small n the curve is not monotone and looks strange. This is because Sn/n is discrete: with Rademacher and n = 10, the average can only be −1, −0.8, …, 0.8, 1, so |Sn/n| > 0.01 just means Sn ≠ 0, which happens with probability 1 − C(10,5)/2¹⁰ ≈ 0.75 (simulated: 0.756). For odd n, Sn = 0 is impossible, so the probability is exactly 1.
  • The LLN talks about the whole distribution across attackers, but the trajectories in section 2 show the same thing path by path: each path of Sk/k eventually stays close to μ (this is the strong LLN, almost sure convergence, which is stronger than what we were asked to check).

5Central Limit Theorem: Sn/√n → N(0, 1)

Convergence in distribution in the Rademacher case (and the centred version for Bernoulli).

The CLT says that for i.i.d. increments with finite variance

Zn = (Sn − nμ) / (σ√n)  →  N(0, 1)   in distribution,

i.e. P(Zn ≤ x) → Φ(x) for every x. For Rademacher μ = 0, σ = 1, so Zn = Sn/√n exactly. To measure "how close" the distribution is to the normal I used the Kolmogorov-Smirnov distance Dn = supx |Fn(x) − Φ(x)|, which is exactly the quantity that convergence in distribution says goes to 0 (Φ is continuous everywhere).

Comments.

  • The shape converges to the bell curve. At n = 1 the "distribution" is two spikes at ±1, at n = 4 it's 5 spikes, and already around n = 30 the histogram is hard to tell apart from N(0,1) by eye. The variance is 1 for every n (section 3), only the shape changes.
  • The rate is 1/√n. The exact KS distance for Rademacher was 0.123, 0.0398, 0.0126, 0.00399, 0.00126 for n = 10 … 100,000: every ×100 in n divides it by 10. It actually matches 0.399/√n = 1/√(2πn) almost perfectly. The reason is nice: Sn/√n is a lattice variable (step 2/√n) and its cdf jumps at 0 by P(Sn = 0) ≈ √(2/(πn)), while Φ is continuous, so the cdf can't be closer than half of that jump. The Berry-Esseen theorem gives the general bound Dn ≤ C·E|X|³/(σ³√n) with C ≤ 0.4748, which for Rademacher is 0.4748/√n, so the symmetric case is close to the worst case allowed by the theorem.
  • Bernoulli (centred). With p = 0.3 the same happens but convergence is a bit slower at the start (D = 0.150 at n = 10 against 0.123), because the distribution is skewed: skewness of the sum is (1 − 2p)/√(np(1 − p)), which only goes to 0 like 1/√n. With p closer to 0 or 1 it's much worse (try p = 0.05 in section 4: at small n the histogram is a one-sided spike, and it takes far more systems to look normal).
  • The number of attackers limits what we can see. The simulated KS distance follows the exact one only until it reaches about 0.87/√m (≈ 0.0087 for m = 10,000), and then it stops decreasing: at n = 10,000 and n = 100,000 the simulation gave 0.0081 and 0.0086 even though the true distance was 0.004 and 0.0013. This is because with m samples the empirical cdf itself has an error of order 1/√m (the average of √m·D for a perfect sample is √(π/2)·ln 2 ≈ 0.87). So "suitable m" means: to check the CLT at size n we need m to be at least comparable with n, otherwise the Monte Carlo noise is bigger than the effect we want to measure.
  • Convergence is in distribution only, not in probability: Sn/√n doesn't settle down to a value for any single attacker (look at the trajectories in section 2, they keep oscillating), it's only the histogram across attackers that stabilizes.

6Interpretation: n systems and m attackers

What the results mean for the aggregate penetration score.

The effect of the system size n

  • Total score. The number of penetrated systems Sn grows linearly (np), and its uncertainty grows too, but only like √n. So in absolute terms a bigger infrastructure means more compromised systems and more uncertainty about how many.
  • Average score. In relative terms it's the opposite: the fraction of compromised systems Sn/n becomes almost deterministic (LLN). With 10 systems an attacker with p = 0.3 can get anything from 0% to 60%; with 10,000 systems about 95% of the attackers end up between 29% and 31%, and even the luckiest out of 10,000 only reached 31.8%. For a defender this means that in a large system the fraction of losses is predictable from p alone, and luck doesn't matter much anymore. The only way to reduce it is to reduce p.
  • Normalized score. Sn/√n measures the fluctuation around the expected value at its natural scale. In the balanced Rademacher case it says that after n systems an attacker is typically ±√n "points" away from zero, with a Gaussian distribution, no matter what the details are. So even when attacker and defender are perfectly balanced (mean 0), some attackers get far ahead just by chance, and how far grows like √n.

The effect of the number of attackers m

The m attackers can be looked at in three ways, and m plays a different role in each:

  1. As repetitions. Each attacker is an independent sample, so m controls how well we can estimate the distributions. The Monte Carlo error is of order 1/√m (see the KS noise floor in section 5). It doesn't change the distribution of a single attacker's score.
  2. As a team (sum over attackers). The total score of all attackers T = S(1)n + … + S(m)n is again a sum of mn i.i.d. increments, so everything above applies with mn instead of n: mean mnμ, variance mnσ², and the average per attacker per system concentrates even faster.
  3. As a threat (best attacker, or "at least one" attacker). This is the view that matters for the defender. The best of m attackers has an average score of roughly μ + σ·cm/√n, where cm is the expected maximum of m standard normals (1.54, 2.51, 3.24, 3.85 for m = 10, 100, 1,000, 10,000; it grows like √(2 ln m), so very slowly). More attackers means a better best attacker, but increasing n kills the advantage because of the 1/√n.
Average score of the best attacker out of m, from the Python simulation

Dots: simulation (average over 50 random groups of m attackers out of the 10,000). Dashed lines: μ + σ·cm/√n from the CLT.

For example with Bernoulli p = 0.3 and n = 100 systems, a single attacker gets about 30%, but the best of 100 attackers gets 41% and the best of 10,000 gets 48%. With n = 10,000 systems the same numbers become 30.1%, 31.2% and 31.8%. In the Rademacher case the average of the best attacker goes to 0 as well, but its total doesn't: it's about cm√n, so for n = 10,000 and m = 10,000 the luckiest attacker is about 380 points ahead (simulated: 376) even though every attacker has zero expected score.

Defender's view

Bernoulli model with m independent attackers on n systems. A system is compromised if at least one attacker gets in, which happens with probability q = 1 − (1 − p)m. The number of compromised systems is again a sum of n i.i.d. indicators, so it is Bin(n, q) and the LLN and CLT apply to it too.

This last calculation shows the real problem for a defender: even if each attacker has a small chance per system, the union over attackers grows quickly with m (with p = 0.1 and m = 20 attackers, 88% of the systems fall). The LLN then says the number of compromised systems will be very close to nq when n is large, so the "aggregate" outcome is essentially decided by p and m, not by chance.

Limits of the model

All of this depends on the i.i.d. assumption. Real attacks are not like that: once an attacker is inside one system it is usually easier to move to the next (lateral movement), attackers share information, and systems are not identical. Positive dependence between steps would make the variance of Sn grow faster than n, so the LLN would converge more slowly and the CLT approximation could be very wrong in the tails. Also p would not be fixed, since defenders react after the first intrusions. So the model is good for understanding the basic scaling (n vs √n), but a real risk analysis would need dependence.

7Conclusions

  • Sn has variance nσ² and spreads out, Sn/n has variance σ²/n and collapses on μ, Sn/√n has constant variance σ². The simulations matched these within about 2-3% for every n.
  • LLN: P(|Sn/n − μ| > ε) goes to 0 for both models, much faster than the Chebyshev bound, but you need n ≫ σ²/ε² before it is small. For small n the discreteness of the score is visible.
  • CLT: in the Rademacher case Sn/√n approaches N(0,1), with a KS distance of almost exactly 0.4/√n. For Bernoulli it works after centring, a bit slower because of the skewness. To see this in a simulation m has to grow with n, because the Monte Carlo noise floor is about 0.87/√m.
  • In terms of systems and attackers: more systems make the fraction of losses predictable (LLN), but the absolute losses and their fluctuations still grow. More attackers don't change what a typical attacker does, but they push up the best attacker (slowly, like √(2 ln m)) and the number of systems hit by at least one attacker (quickly).

function simulate(model, p, n, m) {
  const final = new Float64Array(m);       // S_n of every attacker
  for (let a = 0; a < m; a++) {            // m attackers
    let S = 0;
    for (let i = 1; i <= n; i++) {         // n systems
      if (model === "bern") { if (rng() < p) S++; }
      else S += rng() < 0.5 ? 1 : -1;
    }
    final[a] = S;
  }
  return final;                            // then look at final, final/n, final/sqrt(n)
}
